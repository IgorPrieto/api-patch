# Matriz de compatibilidad — APIPatch 0.1

[English](COMPATIBILITY.en.md) · [Español](COMPATIBILITY.md)

«Soportado» significa que el patrón tiene implementación y pruebas; no que cualquier programa que lo contenga pueda repararse. Cada informe incluye cambios, evidencias, confianza, pendientes y límites. Las equivalencias semánticas solo se aceptan desde el archivo de migración.

| Área | Soportado | Revisión manual o fuera de alcance |
| --- | --- | --- |
| Definiciones | OpenAPI 3.0.x/3.1.x, JSON/YAML; rutas, métodos, parámetros, cuerpos, respuestas y requisitos de seguridad; `$ref` local bajo raíz permitida y referencias recursivas acotadas, incluso en `dependentSchemas`/`contentSchema`. Un documento 3.1 sin `paths` carga. | Referencias remotas, `$dynamicRef`, `$anchor`, dialectos JSON Schema completos, archivos fuera de raíz, documentos que exceden límites. Los webhooks 3.1 se aceptan como documento, pero no se comparan y generan diagnóstico. Una referencia inválida produce error, no un análisis incompleto oculto. |
| Comparación | Operaciones eliminadas o añadidas, método como eliminación/adición, parámetros obligatorios/retirados, tipos, enum, requisitos y propiedades de petición/respuesta, respuesta HTTP, medios y requisitos de autenticación. Las reglas consideran dirección de petición y respuesta. Las referencias recursivas de esquema se comparan estructuralmente con detección de ciclos; las ramas de `allOf` con forma de objeto se combinan y se comparan con las reglas normales; añadir o retirar ramas de `anyOf` se clasifica según la dirección. | Renombres semánticos, esquemas de autenticación completos, `style`/`explode`, encoding, cabeceras de respuesta, links, callbacks. Los cambios en `oneOf`, `not`, `if`/`then`/`else`, discriminator y `allOf` no combinables son ambiguos; las ramas de `anyOf` se emparejan por posición. Una referencia recursiva que no se puede resolver se marca ambigua. Las variaciones no interpretadas se marcan ambiguas cuando se detectan; no se declaran compatibles por defecto. |
| Repositorios | JavaScript/TypeScript `.js`, `.jsx`, `.ts`, `.tsx`, `.mjs`, `.cjs`, `.mts`, `.cts`; AST de TypeScript; `fetch`, importaciones directas de `node-fetch`/`cross-fetch`, `axios`, `axios.create`, `require('axios')`; métodos HTTP literales; URL literal, plantilla con segmentos dinámicos simples, constantes locales inmutables, concatenación simple y `new URL` resoluble. | Wrappers propios, valores mutables, flujo entre módulos, método/URL calculado, instancias axios con base no resoluble, transformaciones complejas. Una base desconocida solo puede aportar una pista de baja confianza, nunca un destino confirmado. |
| Asociación | Archivo y rango, método/ruta, candidato de operación, evidencia AST/esquema, confianza y motivo. Origen de la llamada se compara con los servidores cuando está disponible. | Texto parecido por sí solo no prueba una llamada ni autoriza un parche. URL de tercero o método desconocido se dejan sin vínculo de alta confianza. |
| Reparación | Mapeo explícito de operación con mismo método/servidor, renombre de query, clave superior de cuerpo JSON, acceso directo a propiedad de respuesta y valor literal configurado; objetos y URL editables dentro de la llamada; vista previa, diff y aplicación explícita con hash. | Usos `unresolved` o de confianza baja, cambios ambiguos, método/servidor, campos anidados, spreads/computed, URL/objeto compartido, `+` para una URL editable, destructuring o accesos dinámicos a respuesta, transformaciones cuyo destino no figure en OpenAPI. Pueden quedar parcialmente resueltas con pendientes explícitos. |
| Verificación | Niveles 1 (plan), 2 (sintaxis), 3 (tipos cuando son comprobables), 4 opt-in para el contrato de la demo empaquetada y 5 (comando del repositorio solo con autorización explícita). Nivel 4 ejecuta tres casos soportados contra v2 en copia temporal y deja `preferences` pendiente. | No hay generador universal de pruebas de contrato para cualquier API/consumidor. Sin `--demo-contract`, el nivel 4 aparece `skipped`; un plan ajeno a la demo queda `blocked` sin ejecutar código. Los niveles bloqueados/omitidos nunca cuentan como éxito. La demo sintética no acredita producción. |
| Panel local | Selección de OpenAPI y repositorio bajo el workspace autorizado, URL base y migración; análisis real, revisión de hallazgos, archivos y diff, niveles de verificación, exportación JSON/Markdown/patch y aplicación con confirmación. Servidor en `127.0.0.1`, token de sesión, pruebas HTTP y e2e Chromium. | La selección solo alcanza rutas dentro del workspace dado a `ui`; el panel no ejecuta pruebas del repositorio ni un contrato arbitrario. Para nivel 5 usa la CLI con autorización explícita. |

Límites detallados: [reglas de comparación](../src/compare/RULES.md), [reparaciones](../src/repair/REPAIRS.md), [arquitectura](ARCHITECTURE.md) y [aceptación](ACCEPTANCE.md).
